# 书库首页空白与网络连接问题

## 已经确认的情况

用户在 iPhone 上反馈：Wi-Fi 下“发现”和“排行”能显示，首页只剩快捷按钮；切换蜂窝网络时曾出现应用内安全连接失败，但同一手机的 Safari 能访问两个接口，而且失败似乎是偶发的。

源码中的接口地址是固定的，没有按用户 IP 改写地址。服务端仍可能按照网络出口返回不同内容；目前没有拿到这台手机失败时的响应，不能把这一猜测写成确定原因。

两端存在同一个错误处理缺口：`homeIndex` 返回成功，但 `results` 为空、字段不认识或无法解析时，原代码仍返回一个没有内容的首页对象。页面随后停止加载，既没有漫画，也不显示错误。这一情况已使用模拟接口在测试中复现。

iPhone 端还有一个解析差异：原代码把整个列表转换为字典数组；列表混入一个 `null` 或非字典内容时，会丢掉这一整组数据。现在两端都逐项提取有效字典，不让一个异常条目影响其余漫画。

## 2026 年 10 月 10 日的电脑检查

- 使用应用的请求头访问 `api.copy2000.online/api/v3/h5/homeIndex`，返回 HTTP 200、业务代码 200，包含推荐、日榜、周榜、月榜、更新、新书、完结、专题和横幅。
- 改用 iPhone Safari 的 User-Agent，以及修改 `region` 请求头，电脑上仍返回相同的首页字段。这不能替代用户手机的网络测试。
- `api.copy2000.online` 和 `www.manga2026.xyz` 均通过正常证书校验，并完成 TLS 1.3 连接。主接口当时只有 IPv4 地址，备用服务同时有 IPv4 和 IPv6 地址。
- 备用服务的漫画目录和排行榜已实际请求成功。两个服务的聚合首页结构不同，因此没有把备用聚合首页直接当成同一种格式使用。

这些结果说明电脑端可以正常访问，不能证明用户蜂窝网络上的每一次连接都正常，也不能仅凭白屏确定手机收到的是空对象。

## 本次修复

1. 首页数据为空或没有可识别漫画时，明确报错，不再缓存为成功页面。
2. 不读取本地缓存的旧首页响应；临时空首页再请求一次，恢复时继续使用原推荐和横幅。
3. 聚合首页仍失败时，分别请求新书、热门更新、完结、日榜、周榜、月榜和专题。能恢复的内容照常显示，并提供“查看加载详情”。独立目录没有返回的推荐和横幅不会被编造。
4. 临时连接中断、握手失败等只重试一次，并使用新的连接池或会话。主接口连接仍失败时，目录请求可使用同一提供方已验证的备用 HTTPS 服务，保留原筛选和分页参数。
5. iPhone 书库请求明确允许使用蜂窝数据和低数据模式；这不能覆盖 iOS 系统对某个应用的蜂窝权限限制。
6. 保留系统证书校验。没有关闭 TLS 校验，没有改用 HTTP，也没有重写漫画图片 CDN 的域名。
7. iPhone 错误信息保留错误编号；若系统明确报告禁止蜂窝访问，会提示检查该应用的蜂窝权限。用户取消请求时不会继续开始备用请求。

## 手机上进一步定位

如果修复版仍出现问题，查看页面的错误文字或“查看加载详情”。这能区分首页空对象、字段变化、连接失败和 iOS 错误编号。旧版本的截图没有这些信息，因此手机上那次失败的根因仍需实际响应或错误编号才能确认。

客户端的有限重试可以恢复短暂故障；如果两个 HTTPS 服务在某个网络上都持续无法连接，或图片 CDN 本身连接失败，应用会如实显示错误，不能保证通过重试解决外部网络故障。
