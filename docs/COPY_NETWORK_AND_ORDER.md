# 首页、搜索连接、卷数排序和阅读限流检查

本次针对截图中的四个问题：iOS 首页每次打开均为空、刷新不恢复；搜索连接超时；阅读数据返回 HTTP 429；《出包王女》卷数乱序。iOS 和 Android 使用相同的修正规则。

## 已查明的原因

- 旧搜索代码只访问 `www.2026copy.com`，搜索接口没有备用地址。本机绑定物理 Wi-Fi 网卡直连时，该域名连接被重置；同一电脑通过代理能访问。[拷贝官网](https://www.2026copy.com/)明确提供的大陆地址是 `https://www.copy4000.com/`，其网页搜索接口在桌面两条路线均返回成功，但原生直连检查仍发现偶发超时。最终优先使用已验证的 `mapi.hotmangasg.com/api/v3/search/comic` 漫画搜索 API，起始页连接失败时可使用站方网页搜索接口。关键词与界面不变，不加载网站页面。两种搜索接口的搜索范围和总数可能不同，因此翻页固定使用起始页选中的接口类型，重新搜索才可改变，避免混排、跳项。限流及权限拒绝不会触发更换地址。
- 《出包王女》的实际接口中，普通卷是第01～18卷，随后是 D01～18卷，最后是短篇；40项默认章节和1项其它汉化版，共41项。普通卷和 D 卷都只提供标题中的卷数，上传日期同为2018-10-03。旧代码按上传日期、话数和随机章节标识重排，导致同一天的卷数被打乱。现在使用接口的章节 `index` 保留两个系列的顺序，不再用随机标识决定阅读顺序；手动选择按章节排序时，同样支持卷数及 D 系列。升降序、按上传日期排序、开始阅读均遵守这些规则。
- “阅读图片失败：HTTP 429”发生在取章节页面地址的接口阶段，表示服务端限制了请求速度。截图不足以确定具体限额或共享出口的其他流量。本次国内直连和代理下，第188话均成功返回21页，没有刻意制造服务端限流。

- 苹果首页空白在 GitHub 的真实苹果网络请求中复现：成功响应中的全部栏目都为空。随后保持同一出口和其余请求条件，用桌面比较语言头：`en-US,en;q=0.9` 返回全部空数组；`zh-CN,zh-Hans;q=0.9` 和 `zh-Hant,zh;q=0.9` 返回完整首页。这确认接口会根据请求语言返回不同数据。两端现在明确请求中文漫画数据，不依赖系统自动添加的语言头，界面语言设置仍各自保留。手机自己的完整请求头尚未取得，因此不能把所有手机失败都归结为这个原因。

- 真正逐页读取时发现，国内出口连接 `sm.mangafunb.fun` 会被重置，代理出口却能读取。站方的 `sm.mangafuna.xyz` 指向直连 CDN，同一路径返回相同图片（第188话第一页 SHA-256 为 `4055b7004d3799133460249b8d089163edc62eda32974a14c05f9f64fc735ce1`）。另外抽查首页和封面使用的多个 `s*.mangafunb.fun` 分片，能成功访问的对应直连分片均返回相同字节及校验值。两端将站方这些图片别名改用对应直连分片，完整保留路径、尺寸和查询参数。直连 CDN 的部分 DNS 节点仍存在偶发连接重置，因此图片请求支持最多两次新连接恢复，并继续正常验证证书。图片429按服务端等待时间处理，不换地址绕过。

## 阅读请求的处理方式

同一客户端的阅读和下载请求共享页面列表。成功列表在内存中最多保留32章、5分钟，避免连续点击或同时下载再次索取同一列表；失败和权限拒绝不会缓存。不同章节依次取列表，至少间隔0.5秒。

iOS 同时加载漫画资料和章节时，原先会重复请求同一个漫画详情接口。现将该请求合并，成功资料最多保留16部、10秒；章节列表仍单独刷新。

收到 HTTP 429 或 JSON 中的429时，遵守服务器 `Retry-After`（秒数或 HTTP 日期），同一服务的其它请求也遵守等待时间。等待不超过5秒时自动重试，最多再试两次；没有等待头时依次等2秒和4秒。较长等待立即说明剩余时间，避免界面一直转圈。不会通过换 IP、切换域名或关闭证书验证绕过限流。

## 网络验证的边界

系统当前有 TUN 代理，仅添加“禁用 HTTP 代理”参数仍会经过代理。因此直连测试绑定物理 Wi-Fi 网卡，并用 HTTPS 出口查询确认路线不同。已确认的出口分别是国内 IP `61.243.86.*` 和代理 IP `216.167.70.*`。完整地址与各请求状态仅保存在本机的 `android/verification/copy-network/` 中。

原生模拟器测试使用只监听本机的 HTTPS CONNECT 转发通道选择物理网卡，或显式使用现有代理；转发器不会解密 HTTPS，也不改变系统或设备代理设置。测试代码不修改书架、历史记录或账号资料。真实服务检查须显式启用 `copyNetwork=true`，不会加入默认离线测试。

这些检查能证明实际测过的设备、两条路线和测试时刻的表现，不能保证所有运营商、手机或共享代理 IP 都不受服务端限制。iPhone 蜂窝网络和用户手机上的 VPN 仍须用实际设备验证。

## 回归测试

两端使用同一份从实际接口提取的《出包王女》章节字段作为固定回归样本，覆盖默认顺序、卷数升降序、D系列分组、同日期排序和开始阅读顺序。另覆盖搜索超时后的备用请求、关键词及分页保留、429等待与重试上限、长等待期间阻止重复请求、页面请求合并、权限失败及无效数据。

新 iOS 截图说明，独立目录恢复已生效，但原首页始终为空、刷新不恢复。本次增加仅在成功却为空时使用新缓存标识的重试，避免重复读取同一份服务器缓存；仍为空时读取可用的备用首页，保留真实横幅、推荐和专题，再补齐缺失的目录栏目。备用服务的周榜及更新字段与主首页不同，按其实际含义显示，不把周榜标成日榜。诊断详情现在记录字段类型、条目数和有效漫画数，并可在 iOS 上复制。没有手机的原始响应，不能仅凭字段名断定是手机 IP、缓存还是条目格式造成的空结果。

原生 Android 8 的国内路线实测还发现 HTTP/2 请求漫画详情时超时。Android 的一次连接恢复尝试现在使用新的连接池和 HTTPS 上的 HTTP/1.1；后续同一客户端可沿用成功的协议。两端增加已实际验证的拷贝内容备用服务 `https://mapi.hotmangasg.com`，网络或服务器故障时保留原路径和参数切换，并记住可用路线。其首页、漫画详情、章节列表、第188话的21页在本次检查中均返回成功。不会拿返回“升级官方 APP”限制的接口充当备用阅读服务。

备用目录有一项已确认的限制：旧接口会忽略新版的 `top=finish`、状态和地区筛选，返回全部漫画。例如相同请求在主接口是16,302部完结作品，旧备用接口却是122,488部全部作品。加上中文请求语言及刷新标识仍相同。因此两端在主筛选目录连接失败时明确提示，不把备用的全部漫画冒充完结作品；备用首页也不会补入这份错误的完结栏目。主接口正常时，原有筛选照常使用。通用目录、题材、搜索和章节不受这条保护影响。

备用请求收到限流时，等待时间和限流错误类型会原样向上传递，首页恢复流程也会停止；不会把它包装成普通连接错误后继续恢复请求。Android 图片请求保留正常的同协议跳转，避免这次网络调整影响本来需要跳转的图片。

iOS 已收藏的漫画默认先读取本地章节缓存。装新版后，在这类漫画详情页下拉刷新一次，才会用最新接口顺序更新旧缓存；原有已读进度和下载记录继续保留。Android 打开详情页时会请求更新，并把新顺序合并到原记录。

设备测试可用 `-PverificationApplicationId=app.monogatari.android.verification` 编译独立安装，不覆盖现有物语。此属性不改变默认安装包的名称或身份。
